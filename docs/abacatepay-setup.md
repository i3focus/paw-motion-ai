# AbacatePay setup — partner credit purchases

Step-by-step guide to enable real credit purchases in PETLIFE through the
AbacatePay hosted checkout (PIX / card). Covers the AbacatePay dashboard
configuration and the matching `.env` values.

## How the flow works

1. Partner chooses an amount in whole BRL in the partner portal.
2. Backend creates a `payment_transaction` row and calls
   `POST /checkouts/create` (`AbacatePayHostedCheckoutAdapter`).
3. Partner is redirected to the AbacatePay hosted page and pays.
4. AbacatePay POSTs a webhook to `/api/webhooks/payments/abacatepay`.
5. `ProcessPaymentWebhookService` verifies the secret + signature and credits
   the partner's wallet. `credits = BRL × BILLING_CREDITS_PER_CURRENCY_UNIT`.

## Step 0 — Prerequisites

- AbacatePay account with **company verification** (production payments; test
  mode works without it)
- **2FA enabled** on the account — required before API keys can be created

## Step 1 — Configure the product (dashboard)

### How the quantity math works — read carefully

An AbacatePay checkout is a shopping cart: we send a list of items, each with a
product `id` and a `quantity`. The total charged to the partner is:

```
total = product unit price × quantity
```

Our adapter sends **one item** whose `quantity` equals the purchase amount in
whole reais:

```kotlin
// AbacatePayHostedCheckoutAdapter.createCheckout
"items" to listOf(mapOf(
    "id" to properties.creditProductExternalId,        // your product
    "quantity" to request.amount.intValueExact()))      // amount in BRL
```

So when a partner buys **R$50** of credits, the payload is:

```json
{"items": [{"id": "prod_qtJLGHSbGzr5m2ZUKUczSh4F", "quantity": 50}]}
```

and AbacatePay charges `50 × <product unit price>`.

| Product unit price | Partner buys R$50 | Actually charged | Result |
| --- | --- | --- | --- |
| **R$1,00** | quantity 50 | 50 × R$1 = **R$50** | correct |
| R$10,00 | quantity 50 | 50 × R$10 = **R$500** | partner overcharged 10× |
| R$50,00 | quantity 50 | 50 × R$50 = **R$2.500** | partner overcharged 50× |

Therefore the product **must be priced at exactly R$1,00 per unit**. Think of
it as "R$1 of platform credits" — buying R$50 means buying 50 of them.

### What to do in the dashboard

1. Open **Produtos** and edit the credit product
   (`prod_qtJLGHSbGzr5m2ZUKUczSh4F` — already in `.env`).
2. Set its **price to R$1,00** (BRL 1.00 per unit).
3. Keep the product ID in `ABACATEPAY_CREDIT_PRODUCT_EXTERNAL_ID`.

> Want a different model — e.g. a fixed "R$69,90 credit pack"? That requires a
> code change (send `quantity: 1` and a fixed amount), not just configuration.
> Ask before changing the price model.

### Whole-reais rule

`PurchaseCreditsService.validate` rejects non-integer amounts
(`"Purchase amount must be a whole currency unit"`), and `intValueExact()`
would fail on decimals anyway. Consequences:

- With `BILLING_MIN_PURCHASE_AMOUNT=69.90`, the effective minimum purchase is
  **R$70** — R$69,90 itself is not a whole unit and gets rejected. Use `69` or
  `70` if R$70+ is not the intent.
- Prices like R$49,90 are impossible in this model. Fine if purchases are
  round values (R$50, R$100, ...).

## Step 2 — Create the API key

Dashboard → **Integração → API → Nova chave**:

1. Choose **API v2**. The adapter targets
   `https://api.abacatepay.com/v2`; a v1 key gets
   `401 API key version mismatch`.
2. Create it in the environment shown by the dashboard toggle:
   - **Modo Teste** → `abc_dev_...` (simulated payments — use this first)
   - **Production** → `abc_prod_...` (real money — later)
3. Grant the minimum permissions the adapter uses:

   | Permission | Endpoint used |
   | --- | --- |
   | `CHECKOUT:CREATE` | `POST /checkouts/create` |
   | `CHECKOUT:READ` | `GET /checkouts/get` (status reconciliation) |
   | `CHECKOUT:DELETE` | `POST /checkouts/delete` (cancel pending) |
   | `WEBHOOK:CREATE` | only if registering the webhook via API — not needed with the dashboard |

4. Copy the key immediately — it is shown **only once**.

## Step 3 — Generate the webhook secret

The secret is generated by **us**, not by AbacatePay:

```bash
openssl rand -hex 32   # 64 hex chars (minimum 32)
```

Use the same value in `.env` (`ABACATEPAY_WEBHOOK_SECRET`) and in the webhook
registration below. AbacatePay sends it back in the `X-Webhook-Secret` header
on every delivery; our adapter rejects the request if it doesn't match.
`X-Webhook-Signature` is verified separately with AbacatePay's public key —
already hardcoded in the adapter, nothing to configure.

## Step 4 — Register the webhook

Dashboard → **Integração → Webhooks → Criar webhook**:

1. Version: **Webhook v2**.
2. URL: `https://<your-domain>/api/webhooks/payments/abacatepay`
   - Must be **public HTTPS** — `localhost`, private IPs, and `http://` are
     refused, and redirects are not followed.
   - For local development use a tunnel (`ngrok http 8080`,
     `cloudflared tunnel`, or `abacatepay listen`) and register the tunnel URL.
3. Secret: the value from step 3.
4. Events: `checkout.completed` is **required** (it credits the wallet —
   our handler matches `eventType.contains("completed")`). Also subscribe to
   `checkout.refunded`, `checkout.disputed`, and `checkout.lost` for the
   refund/failure paths.
5. **Environment must match the API key.** A webhook created in Modo Teste
   sends `devMode: true` events; `ProcessPaymentWebhookService` rejects events
   whose `devMode` doesn't match the key prefix
   (`abc_dev_` ↔ test webhook, `abc_prod_` ↔ production webhook). Create one
   webhook per environment.
6. Webhooks are immutable — to change URL/secret/events, create a new one and
   delete the old.

## Step 5 — `.env` configuration

```bash
# Enable the real gateway
PAYMENT_PROVIDER=abacatepay

# From step 2 (abc_dev_... for tests, abc_prod_... for production)
ABACATEPAY_API_KEY=abc_dev_...

# From step 3 — must equal the dashboard webhook secret
ABACATEPAY_WEBHOOK_SECRET=<openssl rand -hex 32>

# From step 1 — product priced at R$1,00/unit
ABACATEPAY_CREDIT_PRODUCT_EXTERNAL_ID=prod_...

# Purchase limits (whole-BRL amounts only — see "Whole-reais rule")
BILLING_MIN_PURCHASE_AMOUNT=70.00
BILLING_MAX_PURCHASE_AMOUNT=10000.00
BILLING_CREDITS_PER_CURRENCY_UNIT=10
```

`ABACATEPAY_API_KEY`/`ABACATEPAY_WEBHOOK_SECRET` are mandatory when
`PAYMENT_PROVIDER=abacatepay` — the adapter fails fast on boot if they're
empty.

## Step 6 — Verify

1. **Key + product (optional isolated check)** — create a checkout directly:

   ```bash
   curl -X POST https://api.abacatepay.com/v2/checkouts/create \
     -H "Authorization: Bearer $ABACATEPAY_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "items": [{"id": "prod_qtJLGHSbGzr5m2ZUKUczSh4F", "quantity": 70}],
       "methods": ["PIX", "CARD"],
       "completionUrl": "https://example.com/return",
       "returnUrl": "https://example.com/return"
     }'
   ```

   The response `data.url` is a hosted page whose total must be **R$70,00**.
   A different total means the product price is wrong — go back to step 1.

2. **End-to-end (Modo Teste)**: restart the backend (`./gradlew bootRun`),
   open the partner portal, buy credits → you land on the AbacatePay page →
   click the test-mode **simulate payment** → the webhook fires → the wallet
   shows the credited balance and the transaction becomes `PAID`.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `401` on API calls | wrong key, or v1 key on the v2 API, or missing `CHECKOUT:*` permission |
| Boot fails: "ABACATEPAY_API_KEY and ABACATEPAY_WEBHOOK_SECRET are required" | `PAYMENT_PROVIDER=abacatepay` but env vars empty |
| `Invalid webhook secret` | `.env` secret ≠ dashboard webhook secret |
| `Webhook devMode does not match environment` | dev key + prod webhook (or vice versa) — create the webhook in the same environment as the key |
| `Purchase amount must be a whole currency unit` | non-integer BRL amount (e.g. 69.90) — amounts must be whole reais |
| Checkout total ≠ requested amount | product is not priced R$1,00/unit — see step 1 |
| Webhook never arrives | URL not public HTTPS, redirect in front of it, or endpoint slower than 30 s |
| Credits never appear | webhook not subscribed to `checkout.completed`, or event rejected (check logs for `WebhookVerificationException`) |
